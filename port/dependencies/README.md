# Native dependencies for the newer toolchain

The experimental full Ruby build uses the coherent Fil-C compiler/runtime at `9d1ed206e0ccfc1ec114471386befeba643a5f86`. Dependencies were compiled afresh into `/compiler/source/pizfix` in `ruby-filc-toolchain`. No released optfil libraries were copied into that prefix. The local Docker images still use released optfil.

## Source identity

- libffi 3.8.0: archive and `libffi.projeny` from the existing pinned Fil-C checkout. Archive SHA256 `7da3e2d9a171eb0a038f592ecad3ff2bb2550f3496d87b3b29ad0cf4430c0db4`.
- OpenSSL 3.6.5: `https://deb.debian.org/debian/pool/main/o/openssl/openssl_3.6.5.orig.tar.gz`, SHA256 `a2157c2830efdec3788939b00c9b0638306d3f0bbb76dc4832ee503bb397df98`. This matches the release asset digest retrieved through gh-agent. The pinned `openssl.projeny` expects BLAKE3 `1f7fe0f6b2d9c46f70eee94d4e8700cf754623e9764af424e3eb9a9127d77999`, which also matches. The archive was placed in projeny's verified snapshot cache; no descriptor URLs or patches were changed. The NLUUG mirror returned 404 before the Debian download succeeded.
- zlib 1.3.2: `https://zlib.net/fossils/zlib-1.3.2.tar.gz`, SHA256 `bb329a0a2cd0274d05519d61c667c062e06990d72e125ee2dfa8de64f0119d16`. Comparison with the pinned Fil-C tree found only `crc32.c` and generated `zconf.h` different. `zlib-1.3.2-filc.patch` reproduces the existing Fil-C ARM CRC assembly selection change exactly; the resulting crc32.c Git blob is `e949ad80f41ac246191c2243f4ffd4358364efed`. zconf.h is generated by configure.
- libyaml 0.2.5: existing verified archive, SHA256 `c642ae9b75fee120b2d96c712538bd2cf283228d2337df2cf2988e3c02678ef4`. Its source matches the pinned Fil-C tree except for the absent `configure.txt` notes file.

Archive comparison: `../compare-dependency-archives.py`, `../../ta/current-toolchain-dependency-source-comparison.log`. Build driver: `../build-current-toolchain-dependencies.sh`. Build directory is recorded in `../../ta/current-toolchain-dependencies-path.txt`, currently `/compiler/ruby-native-deps-GXlkbk`.

## Validation and restored omissions

zlib's static/shared/64-bit checks and libyaml's two tests pass. libffi has 1742 expected passes and two unsupported Go closure cases. Its separate callback/call probe also passes. Logs and individual exit statuses are in `../../ta/dependency-current-*`.

OpenSSL's Fil-C-configured suite passed 348 recipe files / 4554 tests, but that is not the complete upstream suite: the pinned port deletes eight recipes and skips the QUIC radix recipe. The omitted recipes were restored from the identical upstream archive, not replaced with weaker tests:

| Recipe | Observed result |
|---|---|
| symbol_presence | Fails; expected ordinary symbol names differ from the exported Fil-C names. An ABI-aware audit is still needed. |
| mem_alloc | Explicit `Cannot do secure malloc in Fil-C` trap |
| mem_alloc_custom_fns | Same secure-malloc trap |
| bioprint | Initially trapped; corrected test arguments now pass |
| param_build | Same secure-malloc trap |
| afalg | Pass |
| secmem | Same secure-malloc trap |
| shlibload | Pass |
| quic_radix, without its unconditional skip | Pass |

`openssl-bioprint-arguments.patch` fixes the existing test's variadic arguments: it passed strings through the integer member of a union, discarding pointer provenance before `%s` read them. Two string entries also had integer type tags. The patch passes string pointers as pointers, retains numeric arguments as numbers, and leaves all expected strings, return values, count assertions and cases intact. It changes test code only, not libcrypto. The intermediate width-only correction exposed the same issue in the `%n` cases; that red result is preserved with `.before-n-arguments` suffixes.

The restored selection now runs nine recipes / 20 top-level tests and still fails five recipes: four explicit secure-malloc limitations and the symbol-name check. `../../ta/dependency-current-openssl-omitted-fixed.{log,status}` records exit 2. Earlier uncorrected results remain at `dependency-current-openssl-omitted.*`; direct native traces are `openssl-current-*.log`.

`../check-openssl-omitted-tests.sh` restores the recipes in a fresh dependency build, applies the test argument correction and runs the selection. The dependency build driver now ends with this audit and propagates its failure rather than presenting the configured subset as complete validation. The original successful dependency-build status predates this audit integration. Secure allocation is deliberately rejected in the upstream Fil-C OpenSSL port; no fake success or ordinary-allocation replacement was added.

## Ruby integration

`../finish-current-toolchain-ruby.sh` rebuilds and installs the shared Ruby and extensions against these dependencies. Loaded-library inspection confirms libssl, libcrypto, libffi, libyaml, zlib, libc and the Fil-C runtime all come from the matching prefix. CA certificates and timezone data use the container's ordinary data files, not its native development libraries.

The full newer-toolchain Ruby run has 34 test-all failures / 17 errors and one new OOM kill. Bootstrap and optional C-API specs pass. Fresh nio4r/Puma builds, HTTPS, the native overflow smoke check, packaged regressions and IRB pass. This toolchain is not a validated replacement for the current Docker images. See `../STATUS.md` for exact counts and limitations.
